# CRC 可視化 SPA 仕様

LFSR（ハードウェア）の動きと、ビット単位 CRC 実装（ソフトウェア）の各行を、1 クロックずつ同期させて見せるブラウザアプリ。用語と表記は「16. 用語と表記」に従う。

## 1. CRC パラメータ（Rocksoft モデル）

| 名前     | 型   | 制約                                                |
| -------- | ---- | --------------------------------------------------- |
| `width`  | 整数 | 1〜32                                               |
| `poly`   | 整数 | 0 < poly < 2^width（最上位の x^width 項は含めない） |
| `init`   | 整数 | 0 ≤ init < 2^width                                  |
| `refin`  | 真偽 | 真なら入力の各バイトをビット反転してから投入する    |
| `refout` | 真偽 | 真なら最終レジスタ値を `width` ビットで反転する     |
| `xorout` | 整数 | 0 ≤ xorout < 2^width                                |

プリセットは reveng カタログの検査値（check、入力 `"123456789"` の CRC）を持ち、計算の正しさの基準にする。

- 教材用 `CRC-3/TUTORIAL`（width=3, poly=0x3, init=0, refin=false, refout=false, xorout=0, 入力ビット `10101`, CRC=`101`）
- reveng の「Catalogue of parametrised CRC algorithms」にある、`width` が 32 以下の全てのアルゴリズム（104 個）。並びはカタログの順。各プリセットはカタログの別名を全て持ち、資料でよく使われるものを先に並べる。
- 選択肢には正式名に続けて、別名のうち先頭から最大 3 つを全角括弧で添える（例: CRC-16/KERMIT（CCITT、CCITT-TRUE、CRC-CCITT））。同じ「CRC-幅/」で始まる別名はその接頭辞を省く。

## 2. 入力

入力形式は次の 3 つから選ぶ。

| 形式            | 例         | ビット列への変換                                  |
| --------------- | ---------- | ------------------------------------------------- |
| 2 進数          | `10101`    | そのまま。長さは任意                              |
| 16 進数         | `31 32 33` | 空白は無視。1 バイト = 8 ビット、最上位ビットから |
| 文字列（UTF-8） | `123`      | UTF-8 でバイト列にし、16 進数と同様に変換         |

- `refin` が真で、ビット長が 8 の倍数でない入力は不正とする。
- 入力ビット数の上限は 256。

## 3. ハードウェアモデル（直接型 LFSR）

レジスタは `r[width-1]`（最上位ビット、左端）から `r[0]`（右端）まで横に並び、1 クロックで左へシフトする。

1 クロックの更新規則は次のとおり。`bit` は入力ビット、`msb` は最上位ビット `r[width-1]`、`feedback` はフィードバックビット。

```
feedback = msb XOR bit
r'[0]    = feedback AND poly[0]
r'[i]    = r[i-1] XOR (feedback AND poly[i])   (1 ≤ i < width)
```

- 図はこの 1 クロックを、擬似コードと同じく「シフト」と「`poly` との XOR」の 2 段に分けて描く（[ADR-0003](adr/0003-diagram-follows-steps.ja.md)）。
- 箱はすべて横線でつなぐ。シフトでは全ての値が右の箱から真横に移り、`r[0]` には右端から 0 が入る。
- XOR ゲートは `poly[i] = 1` の位置 `i`（`i = 0` を含む）ごとに、`r[i]` の真下に 1 つ置く。`r[i]` から下りる左の脚と、下から来るフィードバック線がゲートで合流し、結果が右の脚を上がって `r[i]` に戻る。
- 入力ビットと最上位ビットの XOR ゲートはレジスタ左端の出口に置き、そこからフィードバック線が各ゲートへ伸びる。
- 初期値の 0 埋め（augmentation）は行わない。理由は [ADR-0001](adr/0001-direct-lfsr.ja.md)。

## 4. ソフトウェア表示（擬似コード）

`refin` が偽の場合の擬似コードは次のとおり。`refin` が真の場合は、入力ビットの走査を「バイトごとに反転してから最上位ビットから走査する」2 重ループに置き換える。

```c
crc = init;
if (refin) byte = reflect(byte, 8);
for (bit of inputBits) {
    feedback = ((crc >> (width - 1)) & 1) ^ bit;
    crc = (crc << 1) & mask;
    if (feedback == 1) {
        crc ^= poly;
    }
}
if (refout) crc = reflect(crc, width);
crc ^= xorout;
return crc;
```

- 現在のステップに対応する行をハイライトする。フィードバックビットが 0 のステップでは、`if` の本体を飛ばしたことが分かる表示にする。
- パラメータは名前と値を並べたチップ（例: `poly│0x3`）で書く。`mask` は `width` から作る値なので、`width` のチップとして扱う。
- パラメータが無効で実行されない行（`refin` 偽、`refout` 偽、`xorout = 0`）も消さずに薄く表示し、理由を注記する。どの設定でも 6 つのパラメータすべてがコード上に現れる。

### コードの言語

ソフトウェア表示の見出しの右で、コードを書く言語を選べる。既定は上の擬似コード。

- 選べる言語: 擬似コード、C、C#、TypeScript、Rust、Zig、Python、Ruby、Lua、Perl、Pascal、PowerShell、Bash、Haskell、Erlang、F#。 URL のクエリ `code` での値は順に `pseudo`・`c`・`csharp`・`typescript`・`rust`・`zig`・`python`・`ruby`・`lua`・`perl`・`pascal`・`powershell`・`bash`・`haskell`・`erlang`・`fsharp`。
- どの言語も同じ手順（1 ビットずつ処理する左送り）を、その言語でよく使う書き方で書く。Haskell・Erlang・F# は畳み込み（fold）と関数で書く。
- 各ステップ（`init`・`reflectIn`・`feedback`・`shift`・`xor`・`reflectOut`・`xorOut`・`done`）を実行する行を、どの言語でもちょうど 1 行ずつ置き、上のハイライト・`if` の評価結果・無効な行の注記をどの言語でも同じに扱う。`xor` の行は `feedback` が 1 のときだけ通る分岐の中に置く。
- `refin` が真なら入力をバイトごとに反転してから最上位ビットから処理し、偽なら入力ビットをそのまま処理する。この形は擬似コードと同じ。
- `reflect` やバイトをビットに分ける処理などの補助関数は、定義を省いて呼ぶだけにする。関数の型や引数の宣言は、書かないと形が分からない言語（Haskell・Erlang・F#）だけ書く。
- チップの値はその言語のリテラルで書く。16 進は `0x1021`（Pascal は `$1021`、Erlang は `16#1021`、F# は `0x1021u`）、真偽値は `true`/`false`（Python・Haskell・Pascal は `True`/`False`、Perl は `1`/`0`、PowerShell は `$true`/`$false`）。
- 注記はその言語の行コメント（`//`・`#`・`--`・`%`）で書く。

## 5. ステップ列（状態遷移）

計算は純粋関数 `trace(params, inputBits)` が `Step[]` として返し、描画はステップを読むだけにする。各ステップはその時点のレジスタ値を持つ。

| 種類         | Given                                 | Then                                                                     |
| ------------ | ------------------------------------- | ------------------------------------------------------------------------ |
| `init`       | 計算開始                              | `reg = init`                                                             |
| `reflectIn`  | `refin` 真でバイトの先頭              | 次の 8 ビットが反転した順に並び替わる。`reg` は不変                      |
| `feedback`   | 入力ビット `bit`                      | `feedback = msb XOR bit` が決まる。`reg` は不変                          |
| `shift`      | `feedback` の直後                     | `reg = (reg << 1) & mask`。桁あふれで抜けた元の `r[width-1]` を持つ      |
| `xor`        | `shift` の直後で `feedback = 1`       | `reg ^= poly`。`feedback = 0` ならこのステップは置かず、`shift` で終わる |
| `reflectOut` | 全ビット投入後、`refout` 真           | `reg = reflect(reg, width)`                                              |
| `xorOut`     | `reflectOut` の後（無ければ全投入後） | `reg ^= xorout`                                                          |
| `done`       | 最終                                  | `reg` が CRC。入力の後ろに CRC を連結して表示する                        |

`reflectOut` は `refout` 偽のとき、`xorOut` は `xorout = 0` のときに省く。

## 6. 再生

- 操作: 再生 / 一時停止、1 ステップ進む / 戻る、先頭 / 末尾へ移動、シークバー、速度倍率（0.25〜8）、ループ再生の切り替え。
- ループ再生: 有効なら、再生中に `done` を表示し終えたら先頭に戻って再生を続ける。無効なら `done` で停止する。速度設定と同様、CRC 設定を変えても保持する。
- ブレークポイント: 再生中、次に見せるステップが有効なブレークポイントに当たると、そのステップを見せて一時停止する。再生を押すと続きから再生し、次に当たるところで再び止まる。ループ再生中も止まる。1 ステップ進む・戻る、先頭・末尾へ移動、シークバーでは止まらない。
  - 行のブレークポイント: コードの、ステップを実行する行に付ける。行の番号ではなく、その行が実行するステップの種類に付くので、コードの言語を変えても同じ働きの行に残る。その種類のステップに来るたびに当たる。ヒット回数を指定すると、先頭からその種類のステップに来た回数がちょうどその数になったときだけ当たる（例: `crc ^= poly` の行に 5 を指定すると、5 回目の XOR で止まる）。`feedback` が 0 で飛ばした XOR の行は実行していないので数えない。
  - バイトのブレークポイント: 入力の k バイト目（0 から数える）に付け、そのバイトの最後のビットのクロックを終えたステップ（`feedback` が 1 なら `xor`、0 なら `shift`）で当たる。入力より後ろのバイトに付いたものは当たらない。
  - 各ブレークポイントは有効・無効を切り替えられ、無効なものは当たらない。
- 速度ランプ: 自動モードでは、フィードバックビットが 0 のクロックと 1 のクロックをそれぞれ 1 回以上見せ終わるまで低速（1 ステップ 900 ms）で再生し、その後のクロックは高速（120 ms）にする。片方の値しか出ない入力でも、低速は最初の 6 クロックまでとする。`init`・`reflectOut`・`xorOut`・`done` は常に低速。一定モードでは全ステップ 600 ms。どちらのモードでも時間は速度倍率で割る。
- 設定や入力を変えたら、ステップ列を作り直して先頭に戻り、停止する。
- 設定の保持: CRC パラメータ・入力形式・入力値・速度モード・速度倍率・ループ再生の有無・コードの言語（4 章）・表示言語（17 章）・ブレークポイントを、変えるたびに localStorage に保存し、次に開いたときに復元する。再生位置は保存せず、先頭・停止から始める。保存値のうち形や値の範囲が正しくない項目は、その項目だけ既定値（`CRC-3/TUTORIAL`、自動、×1、ループなし、擬似コード、ブラウザの優先言語から決めた言語、ブレークポイントなし）に戻す。
- 画面割りの保持: サイドバーの開閉と幅、図と下のパネルの境界、擬似コードと経過の境界を、変えるたびに localStorage に保存し、次に開いたときに復元する。見る人の画面に合わせる設定なので、URL のクエリには載せない。保存値が正しくない項目や、今の画面に収まらない値は既定値か収まる範囲に直す。
- URL での共有: 保持する設定と同じ項目を、URL のクエリ（`width`・`poly`・`init`・`refin`・`refout`・`xorout`・`inputMode`・`input`・`speed`・`rate`・`loop`・`code`・`lang`・`bp`。真偽値は `1`/`0`）にも載せ、変えるたびに履歴を増やさずに書き換える。開いたときは、URL にある項目を localStorage の保存値より優先する。URL に無い項目や正しくない項目は、保存値（無ければ既定値）にする。
  - `bp` はブレークポイントをカンマで区切って並べる。行のブレークポイントはステップの種類（`xor` など）で書き、ヒット回数があれば `@` に続けて回数を書く（`xor@5`）。バイトのブレークポイントは `byte` に続けて番号を書く（`byte3`）。無効なものは先頭に `!` を付ける。読めないものは捨てる。
- 設定が不正な場合は、項目ごとのエラーを表示し、描画は直前の有効な状態を残さず空にする。

## 7. 画面

ダークモードの、VS Code のようなエディタ風の画面とし、可視化のページ、名前の規則のページ（8 章）、絞り込みのページ（9 章）、巡回のページ（10 章）、冗長のページ（11 章）、検査のページ（12 章）、置き換えのページ（13 章）、表引きのページ（14 章）、推定のページ（15 章）の 9 つを持つ。この章は可視化のページを定める。

可視化以外のページは、広い画面で右側を大きく空けないよう、内容の塊（カード）を読む順に左から右へ、行が埋まったら次の行へと、横幅に応じた数ずつ並べる（カードはいちばん広い表・ビットの並び・図の幅から始め、文章はその幅で折り返し、行の残りの幅は同じ行のカードで分け合う）。同じ行のカードは上端と高さをそろえ、最後の行のカードは横幅いっぱいに広げる。カードどうしは間を空け、中身をカードからはみ出させない。高いカードの横で大半が空くカードは、1 行を占める。長い一覧（別名の対応表など）も段に分ける。画面より短いページは下を空けたままにせず、図・表・文字を画面の高さに応じて大きくし、ページを下端近くまで届かせる（冗長のページで、符号語が長く全ての並びの格子を出せないときは、本文に付きうる CRC を代わりに正方形に近い格子に並べる）。文章や入力欄の説明を 1 文字ずつ折り返さない。2K や 4K のモニタのように画面が 1600×1000（CSS px）より大きいときは、縦横とも 1600×1000 を下回らない範囲でアプリ全体を拡大し、1600×1000 の画面と同じ並びのまま大きく見せる。拡大しても、分割線はポインタに付いて動く。可視化のページの回路図は、領域の幅に合わせて縮めるが、レジスタの値が読める大きさ（元の大きさの 0.55 倍、スマホでは 0.8 倍）より小さくはしない。それでも領域より広い回路図は横にスクロールでき、ステップごとに計算中の所（最上位のレジスタ、反転するレジスタ、働いている XOR）が見えていなければ、そこまで送る。幅が 700 CSS px 未満の画面（スマホ）では、ページの切り替えを画面の下端（ステータスバーの上）に横に並べ、エディタ領域に横幅いっぱいを使わせ、サイドバーはエディタ領域の上に重ねる引き出しにする。引き出しは初めは閉じ、サイドバーのボタンで開き、中のリンクやボタンを選ぶか、引き出しの外を押すと閉じる。押す所は親指の届く下に置き、押して変わる所はその上で読む。可視化のページの変数（5）は、引き出しではなく、コードと経過の間に置いてともにスクロールし、進めながら読めるようにする。行番号の押す所は指で押せる幅にする。可視化の再生の操作、巡回のページの回すボタンと回したビット列・余り、冗長のページの受け取った並びとそのボタン、検査のページの送る並びは、エディタ領域とページの切り替えの間に置き、ページの残りはその上でスクロールする。可視化のページは、回路図をレジスタの値が読める大きさで上に置き、その下でコードと経過をスクロールし、分割線は出さない。表のページでは、表の値の作り方のカードを 1 バイトずつの計算のカードのすぐ後（表 T の前）に置き、表 T を横に送っても行の見出しを残す。それ以外の図・輪・ビットの並びは画面の幅に合わせて縮め、数字の表は大きさを保ってカードの中で横にスクロールさせる。それ以外に右端からはみ出すものを作らない。

- 画面割り: 画面全体を次の領域に分け、ページ自体はスクロールさせない。領域に収まらない内容は、その領域の中だけでスクロールする。
  - アクティビティバー（左端の細い列）: ページの切替のアイコン（可視化・名前の規則・絞り込み）。
  - サイドバー: 可視化のページでは、設定（設定パネルと説明欄、下の 1）・変数（5）・ブレークポイント（6）の 3 つの区切りを縦に並べ、見出しを押すと開閉する（アコーディオン）。開閉は見る人の画面の都合なので localStorage に保存し、URL には載せない。名前の規則のページでは各節への目次。絞り込みのページでは固定した値と残りの候補。
  - エディタ領域: 上に再生コントロールのツールバー（3）、その下に LFSR 図（2）、さらに下のパネルに擬似コードと経過（4）を左右に並べる。
  - ステータスバー（下端の 1 行）: プリセット名（一致しなければ `custom`）、表示中のステップの種類、処理後の `crc`（2 進と 16 進）。
- サイドバーと各領域の境界はドラッグで動かせる。サイドバーは Ctrl+B（macOS では ⌘+B）とアクティビティバーの切替で開閉できる。
- LFSR 図は、エディタ領域の上部の大きさに合わせて縦横比を保ったまま拡大・縮小する。

1. 設定パネル（サイドバー）: プリセット選択、各パラメータ、入力形式と入力値。
   - 項目名は英語だけで示す。パラメータはパラメータ名（`width`・`poly` など）、それ以外は `preset`・`input mode`・`input` とする。入力形式の選択肢は `bits`・`hex`・`text (UTF-8)`、どのプリセットとも一致しない設定は `custom` と示す。
   - 項目にマウスを乗せると、説明欄に日本語名と説明を出す。パラメータでは別名と注記も出す。
   - パネルの下に説明欄を置き、注目中の項目の日本語名・説明と、パラメータなら別名と設定値に応じた注記を出す。注記は `poly` の反転表記の値と、`refin`・`refout` の組み合わせが右送り・左送りのどちらの実装にあたるか。
   - 説明欄の高さは全パラメータの説明のうち最も長いものに合わせる。横幅によらず説明が見切れず、注目が変わっても画面の配置が動かない。
2. エディタ領域の上部: LFSR 図。入力ストリーム（投入済みは暗く、次のビットは強調）、レジスタ箱、XOR ゲート、`feedback` の箱、フィードバック線。
   - 計算の流れは、配線の色と、配線に沿って動く粒（値 0/1 を書いた丸）だけで示す。図の中に計算式の文字列は出さない（式は擬似コードの注記と経過に出す）。
   - 次の配線は、流れている値で色を変える。どの値も流れていない間は灰色にする。
     - 入力線: 入力ストリーム → 入力ゲート
     - 最上位ビット線: `r[width-1]` → 入力ゲート
     - 結果線: 入力ゲート → `feedback` の箱
     - フィードバック線: `feedback` の箱 → 各タップのゲート
     - タップの入力線: `r[i]` の下辺 → 真下のゲート（左の脚）
     - タップの出力線: ゲート → `r[i]` の下辺（右の脚）
   - 1 ステップのアニメーションの長さは、そのステップの表示時間（速度倍率で割った後）の 80% とし、上限を設けない。速度倍率を下げると粒の動きも同じ比率で遅くなる。
   - 1 ステップのアニメーションを前半と後半に分け、粒は前半か後半のどちらかで動く。

     | ステップ   | 入力線 | 最上位ビット線 | 結果線                 | フィードバック線 | タップの入力線       | タップの出力線         | 前半の粒                                                                             | 後半の粒                                      |
     | ---------- | ------ | -------------- | ---------------------- | ---------------- | -------------------- | ---------------------- | ------------------------------------------------------------------------------------ | --------------------------------------------- |
     | `feedback` | `bit`  | `msb`          | `feedback`（後半から） | なし             | なし                 | なし                   | `bit` と `msb` がそれぞれ入力ゲートへ                                                | `feedback` が入力ゲートから `feedback` の箱へ |
     | `shift`    | なし   | なし           | なし                   | なし             | なし                 | なし                   | なし                                                                                 | なし                                          |
     | `xor`      | なし   | なし           | なし                   | 1                | XOR 前の `r[i]` の値 | XOR の結果（後半から） | 1 がタップごとに `feedback` の箱からそのゲートへ。同時に `r[i]` の値が左の脚を下りる | XOR の結果が右の脚を上がって `r[i]` へ        |
     | 上記以外   | なし   | なし           | なし                   | なし             | なし                 | なし                   | なし                                                                                 | なし                                          |

   - 時間の流れ（1 ステップの中で起こる順）。値は粒が運び、粒より先に結果が見えてはならない。
     1. ステップの始め: 前のステップの表示は持ち越さず、すぐに切り替える。値の流れていない配線は灰色に戻り、前のステップの粒は残さない。粒を伴わない変化（`shift` の滑り込み、`reflectOut` の鏡映、`xorOut` の裏返し、粒の通らない配線の色、最上位ビットの箱の強調）はここで始まる。擬似コードの現在行と経過の新しい行も、ここで切り替える。粒と、粒の後ろから塗る配線は、切り替わった最初の描画から出発の時点まで見せない（後半の粒や塗りが一瞬だけ見えることはない）。
     2. 前半: 前半の粒が出発する。粒が通る配線は、粒の後ろから値の色に塗られ、粒より先には色が付かない。
     3. 前半の終わり: 前半の粒が届いた時点で消える。そのステップで計算に使われるゲートが点灯する。
     4. 後半: 後半の粒（ゲートの結果）が出発し、同じく粒の後ろから配線を塗る。
     5. 後半の終わり: 後半の粒が届いた時点で消え、運んだ値で箱の中身（`r[i]` と `feedback` の箱）が変わる。
     6. 次のステップまでの残り時間は静止する。

   - `feedback` の箱: 入力ゲートの真下に置き、擬似コードの変数 `feedback` の値を示す。`feedback` ステップで結果の粒が届いた時点で値が入り、そのクロックの `shift`・`xor` の間は値を保つ。クロック以外のステップでは空にする。`feedback` の値がゲートへ届くのは `xor` ステップで粒が運んだときだけで、`shift` の間のフィードバック線は灰色のままにする。`feedback` が 0 なら `xor` ステップは来ず、フィードバック線には何も流れない。箱は値の色で塗り（1 は赤、0 は白、空なら灰）、フィードバックが返るクロックかどうかを一目で分かるようにする。色は値と同じく、結果の粒が届いた時点で付く。
   - XOR ゲートは計算に使われるステップ（入力ゲートは `feedback`、タップのゲートは `xor`）でだけ、入力の粒が届いた時点から点灯させる。
   - `xor` で値が変わる箱は、箱の色を変えず、結果の粒が届いた時点で中の値を裏返す。`xorOut` は運ぶ粒が無いので、ステップの始めに裏返す。
   - `shift` では、全ての値が右の箱から真横に滑り込み、`r[width-1]` の元の値は左へ抜けて消える。抜ける値は既に `feedback` の計算に使い終えているので、入力ゲートには入らず、箱の左辺を出たあたりで消えきる。どの値も箱の間隔だけを同じ時間と緩急で動き、同じ速さに見える。`r[0]` の入口（控えの位置）も、`r[0]` の中心から箱の間隔だけ右に置く。
   - 控え: 次のステップが `shift` のとき、右端から `r[0]` に新しく入る値を、`r[0]` の真横（値が入ってくる配線の上）に点線の丸で先に出しておく。`shift` では `r[0]` の新しい値がその位置から真横に入る。色は値の色（1 は赤、0 は白）に従う。隣の箱から移るだけの値は既に見えており、`xor` の結果はゲートから箱へ戻る粒が見せるので、控えは出さない。
   - 入力ストリームのバイトを押すと、そのバイトのブレークポイントを付け外しする。ブレークポイントのあるバイトの下には印を出す（無効なら灰色）。
   - 凡例として、⊕ の意味と色の意味を添える。
3. 再生コントロール（LFSR 図の上のツールバー）。
4. 下のパネル: 擬似コード（現在行をハイライト）と、ステップの経過。
   - 経過は先頭から現在のステップまでを新しい順に並べたログで、各行にステップの種類、関わる入力ビットの番号、処理後の `crc`（2 進と 16 進）、補足（フィードバックビットの式など）を出す。
   - 最新の行だけ大きな文字にし、それより前の行はすべて同じ大きさ・同じ濃さで並べる。表示は最新 40 行まで。ログ欄の高さは固定し、行数によって画面の配置が動かないようにする。収まらない分はスクロールで見る。
   - 行の切り替えは 240 ms かけて動かす。ステップが進むと、新しい行は上から降りながら浮かび上がり、最新だった行は文字が小さくなりながら、他の行とともに下へ滑る。戻すと逆に、新たに最新になった行は文字が大きくなり、残りの行は上へ滑る。
   - コマ戻しやシークをすると、経過もそのステップまで巻き戻る。
   - コードの行番号の左を押すと、その行のブレークポイントを付け外しする。ステップを実行しない行には付けない。ブレークポイントは行番号の左に赤い丸で示し、無効なものは灰色の丸にする。
5. 変数（サイドバー）: 表示中のステップでの、コードの変数の値。
   - `crc`（2 進と 16 進）、`byte`（16 進と、何バイト目か）、`bit`、`feedback`、読んだ入力ビットの数（読んだ数 / 全体）、XOR した回数。
   - `bit` と `feedback` は、そのクロックの `feedback`・`shift`・`xor` の間だけ値を持つ。`byte` は、そのバイトの最初のステップ（`reflectIn` か最初の `feedback`）から最後のクロックの終わりまでだけ値を持つ。値を持たない間は `—` と示す。入力の長さが 8 の倍数でないときは `byte` を出さない。
   - 直前のステップから値が変わった変数は、色を変えて示す。
6. ブレークポイント（サイドバー）: 付けたブレークポイントの一覧。
   - 行のブレークポイントは、そのステップの種類の名前（経過と同じ）と、今のコードの言語でのその行を示す。バイトのブレークポイントは、何バイト目かとその値を示す。
   - 各行に、有効・無効のチェックと、消すボタンを置く。行のブレークポイントには、ヒット回数の入力欄（空なら毎回当たる）と、表示中のステップまでに来た回数も置く。一覧の上に、全部消すボタンを置く。

`done` ではレジスタを緑に光らせ、「入力 + CRC」のビット列を表示する。

## 8. 名前の規則のページ

プリセットの名前の付け方と、パラメータの呼び名の違いを図と表で示す。

- アクティビティバーでページを切り替える。名前の規則のページでは、エディタ領域に下の 1〜5 を並べ、サイドバーに各節への目次を置く。URL のフラグメントが `#names` か `#names/` で始まるなら名前の規則のページ、それ以外なら可視化のページを開く。設定は localStorage と URL のクエリに保つので、ページを切り替えても可視化の設定は変わらない。
- このページの内容はプリセットの一覧（1 章）とパラメータの説明（説明欄と同じもの）から作り、教材用の `CRC-3/TUTORIAL` は reveng カタログに無いので載せない。

1. 名前の分解: `CRC-16/KERMIT` を例に、名前を「CRC」「幅（`width`）」「最初に使われた規格・製品・団体などの名前」に分けて示す。reveng カタログの正式名はこの形で、幅と後半の名前の組で 1 つの設定を指す。
2. 同じ `poly` の一族: 幅と `poly` が同じプリセットが 2 つ以上ある組ごとに、`init`・`refin`/`refout`・`xorout` を表に並べる。各列で、一族の先頭のプリセットと値が違う欄を強調する。一族は幅の小さい順、同じ幅では `poly` の小さい順に並べ、一族の中はプリセットの一覧の順とする。
3. 別名の対応表: 全プリセットの別名を英数字順に並べ、それぞれの正式名を引けるようにする。流儀によって指すものが違う呼び名（`CRC-16-CCITT`）は、候補の正式名を全て挙げた行を別に置く。
4. パラメータ名の別名の図: 可視化の図と同じ部品で描いた固定の LFSR 図（width 3、poly 0x3）に、各パラメータが使われる場所から引き出し線を出し、先にパラメータ名（`poly` など）だけを書く。使われる場所は、`width` がレジスタの並び、`poly` がタップのゲート、`init` がレジスタの箱、`refin` が入力ストリーム、`refout` と `xorout` がレジスタから取り出す CRC の出力とする。
   - パラメータ名にマウスを乗せると、使われる場所を注目中のパラメータの色で強調し、日本語名と別名を小さな札で添える。
   - パラメータ名はリンクで、選ぶと 5 の表のそのパラメータの行へ移り、その行を強調する。URL のフラグメントは `#names/<パラメータ名>` とする。
5. パラメータ名の対応表: パラメータごとに、パラメータ名・日本語名・意味・別名を並べる。別名は説明欄と同じもの（16 章の「別名」）とする。

## 9. 絞り込みのページ

パラメータの値を 1 つずつ固定して、プリセットの候補が 1 つのアルゴリズムに決まるまでをフローチャート（木）で示し、その場で選んでいけるようにする。

- 対象は reveng カタログのプリセット（名前の規則のページと同じく `CRC-3/TUTORIAL` を除く）。
- 固定の道筋: 「パラメータとその値」の組の並びと、最後に開いている分かれ目（値をまだ選んでいないパラメータ）で表す。候補は、道筋の全ての値と一致するプリセットとする。
- 分かれ目: 候補が 2 つ以上ある節では、候補の中で値が 2 通り以上あるパラメータだけを選べる。全ての候補で同じ値のパラメータは分けても意味がないので出さない。固定する順は見る人が選ぶ。
- 木の描き方: 根（全候補）から道筋に沿って節を並べる。各節には、分けたパラメータ名と、その値ごとの枝を値の小さい順（偽が先）に出し、各枝に候補の数を添える。
  - 道筋の枝は開いて次の節を出し、強調する。選ばなかった枝は閉じたまま候補の数だけを出し、選ぶとその節から先の道筋をその枝に替える。候補が 1 つの枝は、プリセットの正式名も添える。
  - 各節では、分けるパラメータの選択肢も出す。今と違うパラメータを選ぶと、その節から先の道筋を捨てて分け直す。
  - 値の表記は、`width` が 10 進、`refin`・`refout` が `true`/`false`、他は大文字の 16 進（`0x1021`）とする。
- 候補が 1 つに決まったら、そのプリセットの正式名と「可視化で開く」を出す。選ぶとそのプリセットの設定（入力も含む）にして可視化のページへ移る。
- サイドバーには、固定した値の一覧と残りの候補の正式名、候補が 1 つなら「可視化で開く」を置く。ステータスバーには残りの候補の数を出す。
- URL のフラグメント: `#narrow` に、固定した値を `/<パラメータ名>=<値>` で順に、開いている分かれ目を `/<パラメータ名>` で最後に付ける（例: `#narrow/width=16/poly=0x1021/init`）。再読み込みや共有で同じ道筋を開く。開いたとき、分けられないパラメータ・候補の無い値・解釈できない部分が現れたら、その手前までの道筋にする。

## 10. 巡回のページ

CRC が「巡回（cyclic）冗長検査」と呼ばれる理由を、同じ生成多項式から作った 2 つの輪の図で示す。

- 生成多項式: `g(x) = x^width + poly(x)`。図の輪が描ける大きさに収めるため、次の小さい生成多項式から選ぶ。設定パネルの値とは連動しない。

  | `g(x)`               | `width` | `poly` | 周期 `n` |
  | -------------------- | ------- | ------ | -------- |
  | x³ + x + 1（既定）   | 3       | `0x3`  | 7        |
  | x³ + x² + 1          | 3       | `0x5`  | 7        |
  | x⁴ + x + 1           | 4       | `0x3`  | 15       |
  | x⁴ + x³ + x² + x + 1 | 4       | `0xF`  | 5        |
  | x⁵ + x² + 1          | 5       | `0x5`  | 31       |

- 周期 `n`: `x^n` を `g(x)` で割った余りが 1 になる最小の `n`（1 以上）。`g(x)` が `x^n − 1` を割り切る最小の `n` でもある。
- 回した数 `k`: 2 つの輪で共有する、0 から `n − 1` の整数。「▶」で 1 増やし、「◀」で 1 減らす（`n` を法とする）。生成多項式を替えると 0 に戻す。URL にも保存にも残さない。
- 符号語の輪: 本文 `n − width` ビットの後ろに、その CRC（本文に `x^width` を掛けて `g(x)` で割った余り。`init` 0、`refin`・`refout` false、`xorout` 0 にあたる）を付けた `n` ビットの符号語を、`x^0` を真上に、次数の大きい方へ時計回りに輪に並べる。本文は `1101` を繰り返した先頭の `n − width` ビットとする。
  - 符号語に `x^k` を掛けて `x^n − 1` で割った余り（`k` ビット回したもの）を描く。各ビットの次数が `k` 上がり、`x^(n−1)` を越えたビットは `x^0` へ回り込む。回すときは輪ごと回るように動かす。
  - 値は 1 を赤、0 を白で塗り、CRC として付けたビットは回しても分かるよう緑の縁で囲む。
  - 輪の下に、回したビット列（次数の大きい方から）と、それを `g(x)` で割った余り（`width` ビット）を出す。何ビット回しても余りは 0 で、符号語のままであることを示す。
- 状態の輪: 3 章のレジスタに `x^0`（`0…01`）を入れ、入力ビット 0 でクロックし続けたときの状態を、`x^0` を真上に時計回りに並べ、順に矢印でつなぐ。`j` 回目の状態は `x^j` を `g(x)` で割った余りで、`n` 回で `x^0` に戻る。
  - 状態は `width` ビットの 2 進で書き、`x^k` の状態を強調する（符号語の輪で `x^k` を掛けたことにあたる）。
- 2 つの輪の下に、次の説明を置く: 輪の長さと状態が戻るまでの回数はどちらも `n`。`x^n` を `g(x)` で割った余りは 1 なので、回り込んだビットの `x^n` を `x^0` に置き換えても `g(x)` で割った余りは変わらない。だから符号語を回しても符号語のままで、この性質を持つ符号を巡回符号と呼ぶ。実際の CRC はふつう `n` より短い入力に使う（巡回符号の先頭を 0 と見なして短くしたもの）。
- サイドバーには生成多項式の一覧を `g(x)` と `n` で並べ、選んでいるものを強調する。ステータスバーには `g(x)` と `n` を出す。
- URL のフラグメント: `#cyclic`（既定の生成多項式）か、`#cyclic/width=<10 進>/poly=<16 進>`（例: `#cyclic/width=4/poly=0x3`）。一覧に無い・解釈できない場合は既定の生成多項式で開く。

## 11. 冗長のページ

CRC が「冗長（redundancy）検査」と呼ばれる理由を、付け足したビットとそれで誤りを見つける様子で示す。生成多項式の選び方・符号語（本文 `k = n − width` ビットと CRC `width` ビット）・サイドバー・ステータスバーは巡回のページ（10 章）と同じ。

1. 何が冗長か: 送る符号語を 1 列に並べ、本文と CRC を色分けして、それぞれのビット数を添える。CRC は本文から計算で決まり、新しい情報は持たないが、この余分なビットで受け取った側が確かめられる、と説明を添える。
2. 符号語は並び全体の一部: `n` ビットの並びは `2^n` 通り、そのうち `g(x)` で割り切れる符号語は `2^k` 通りで、割合は `1/2^width` であることを数で示す。
   - `2^n` が 128 以下（`n` = 5、7）のときは、全ての並びを値の順に格子に並べた図を添える。符号語を緑で塗り、今の受け取った並びを黄の枠で示す。
   - `n` によらず、受け取った本文（`k` ビット）の後ろに付きうる `2^width` 通りの CRC を値の順に並べた帯を添える。符号語になるのはそのうち受け取った本文の CRC の 1 つだけで、これを緑で塗る。届いた CRC を黄の枠で示す。2 つが違うときに限り誤りが見つかる（3 の判定と必ず一致する）。
   - 誤りの入った並びが偶然どれかの符号語になる割合はおよそ `1/2^width` で、`width` を増やすほど見逃しにくくなる、と説明を添える。
3. 誤りを入れて確かめる: 送った符号語の下に、受け取った並びを 1 列に並べる。受け取った並びのビットを選ぶと反転する（誤りを入れる、もう一度選ぶと戻る）。
   - 誤り `e`（送った並びと受け取った並びの XOR）、誤りの長さ（反転した最初のビットから最後のビットまでのビット数。反転が無ければ 0）、受け取った並びを `g(x)` で割った余り、判定を出す。受け取った並びの余りは `e` を `g(x)` で割った余りに等しい、と説明を添える。
   - 判定は 3 通り: 誤りなし（`e` = 0）、誤りを見つけた（余りが 0 でない）、見逃した（`e` ≠ 0 で余りが 0。誤りの入った並びも符号語になっている）。
   - 「元に戻す」で誤りを無くし、「見逃す例」で `e` を `g(x)` そのもの（`x^width` から `x^0` までのビット）にする。その誤りの長さは `width + 1` になる。
   - 必ず見つかる誤りとして、1 ビットの誤りと、長さ `width` 以下の誤りを挙げる。見逃すのは `e` が `g(x)` で割り切れるときだけ、と説明を添える。
   - 誤りは URL にも保存にも残さず、生成多項式を替えると無くす。

- URL のフラグメント: `#redundancy`（既定の生成多項式）か、`#redundancy/width=<10 進>/poly=<16 進>`。一覧に無い・解釈できない場合は既定の生成多項式で開く。

## 12. 検査のページ

CRC が「検査（check）」と呼ばれるところ、つまり受け取った側が実際にどう確かめるかを、今の設定と入力（可視化のページと同じもの）で示す。

- 送る並び: 入力（本文）の後ろに、その CRC を次の順で付ける。
  - `refin` = `refout` = false: CRC を最上位ビットから `width` ビット。
  - `refin` = `refout` = true: CRC を下位のバイトから順に `⌈width/8⌉` バイト（各バイトは 2 章の入力と同じく最上位ビットから書き、計算では `refin` で反転されて最下位ビットから入る）。`width` が 8 の倍数でなければ、最後のバイトの上位は 0。
  - `refin` ≠ `refout`: 符号語ごと通すやり方（下の 2）は当てはまらないので、送る並びは本文と CRC を最上位ビットから付けたものとし、2 には当てはまらない理由を出す。
- 受け取った並び: 送る並びを 1 列に並べる。本文と CRC の間を少し空け、CRC のビットは緑の枠で囲む。下に凡例を置き、本文と CRC のそれぞれのビット数（「本文（72 ビット）」「CRC（16 ビット、緑の枠）」）、値の色（赤 = 1、白 = 0）、反転したビットの印（黄の枠）を、並びのビットと同じ見た目の見本とともに示す。ビットを選ぶと反転し（もう一度選ぶと戻る）、「元に戻す」で全て戻す。反転は URL にも保存にも残さず、設定や入力を変えると無くす。
- 確かめ方を 2 つ並べ、それぞれ計算した値と判定（誤りなし／誤りあり）を出す。
  1. 計算し直して比べる: 受け取った本文の CRC を計算し、受け取った CRC と比べる。一致すれば誤りなし。
  2. 符号語ごと通す: 受け取った並び全体を同じ設定で計算する。誤りが無ければ、本文によらず設定だけで決まる一定の値（残余）になる。残余と一致すれば誤りなし。`xorout` が 0 で反転が無ければ残余は 0。比べる相手が定数なので、回路では本文と CRC を区別せずに確かめられる、と説明を添える。
  - 2 つの判定は、当てはまる限り常に同じになる。
- 検査値: 今の設定がプリセットなら、カタログの検査値（`check`）と、入力 `123456789` で計算した CRC を並べる。検査値は誤りを見つけるためのものではなく、実装が正しいかを確かめる目安だと説明を添える。プリセットでなければ、計算した値だけを出す。
- 検査できないこと: CRC は誤りがあることを知らせるだけで、直さない。また、本文を書き換えた側が CRC も付け直せば見抜けないので、意図的な改ざんへの備えにはならない（ハッシュや MAC を使う）、と説明を置く。
- 設定が不正なときは、送る並び・確かめ方・検査値を出さず、設定が不正であることを出す。
- サイドバー・ステータスバーは置き換えのページ（13 章）と同じ。
- URL のフラグメントは `#check`。

## 13. 置き換えのページ

パラメータどうしの関係を 2 つの節で示す。

### 同じ CRC になる置き換え

値の違う設定や、設定の代わりに入力・出力へ施す操作で、同じ CRC になる関係を一覧で示す。各項目に、左辺（元の設定）と右辺（置き換えた設定や操作）、成り立つ理由の説明、今の設定と入力（可視化のページと同じもの）で両辺を計算した値を並べ、一致することを示す。

| 項目                  | 左辺                      | 右辺                                                                                                                        | 計算例を出す条件                   |
| --------------------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| 入力の反転            | `refin` = true            | `refin` = false にして、入力の各バイトのビットの並びを反転しておく                                                          | 入力がバイト単位（8 ビットの倍数） |
| 出力の反転            | `refout` = true           | `refout` = false にして、出た CRC に `xorout` を XOR し直してからビットの並びを反転し、もう一度 `xorout` を XOR する        | 常に                               |
| 右送りの実装          | `refin` = `refout` = true | 反転をせず、右へシフトするレジスタで、`poly` と `init` はビットの並びを反転した値を使う（LSB から入れ、最下位ビットを見る） | `refin` = `refout` = true          |
| 初期値と前置き        | `init` = I                | `init` = 0 にして、入力の前に `width` ビットの前置き P を足す。P は `P(x)·x^width ≡ I (mod g(x))` を満たす値                | `poly` の最下位ビットが 1          |
| 初期値と最終 XOR の分 | `init`・`xorout`          | `init` = `xorout` = 0 で計算した CRC に、同じ長さの全て 0 の入力の CRC（元の設定）を XOR する                               | 常に                               |

- 「初期値と前置き」では、`init` = 0 のとき入力の前に 0 を足しても CRC が変わらないことと、P を各値の表記（16 進）で添える。
- 「初期値と最終 XOR の分」では、長さの同じ入力 a、b について `crc(a ⊕ b) = crc(a) ⊕ crc(b) ⊕ crc(0…0)` が成り立つこと（`init` と `xorout` の分は長さだけで決まる定数になること）を説明に添える。
- 計算例は、入力の反転（`refin`）を右辺で入力へ施したかたちに直したうえで、両辺を 1 章のパラメータと 3 章のレジスタで計算する。右送りの実装だけは右辺を別の計算（右へシフトするレジスタ）で求める。条件に合わない項目は、計算例の代わりに合わない理由を出す。

### 分かっていることから分かること

パラメータや実装のコードの一部が分かっているとき、そこから決まることを一覧で示す。各項目に、今の設定ではどうなるかを添える。

| 分かっていること                                                     | 分かること                                                                                                                     |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `refin` = `refout` = true                                            | 右送りの実装で、入出力を反転せずに計算できる。その実装のコードには、`poly` と `init` はビットの並びを反転した値で書かれる      |
| `refin` = `refout` = false                                           | 左送りの実装で、入出力を反転せずに計算できる。コードには `poly` と `init` がそのまま書かれる                                   |
| `refin` ≠ `refout`                                                   | 右送りでも左送りでも、どこかで別にビットの並びを反転する処理が要る                                                             |
| 実装のコードが右送り（1 ビット右へシフトし、最下位ビットで分かれる） | 入出力の反転を別に書いていなければ `refin` = `refout` = true。コードの `poly` の定数をビット反転すると通常表記の `poly` になる |
| 実装のコードが左送り（1 ビット左へシフトし、最上位ビットで分かれる） | 入出力の反転を別に書いていなければ `refin` = `refout` = false。コードの `poly` の定数はそのまま通常表記                        |
| コードの `poly` の定数の最下位ビットが 0                             | 通常表記の `poly` は最下位ビットが 1（生成多項式の定数項）なので、この定数は反転した値で、実装は右送り                         |

- 今の設定での補足: 右送り・左送り・どちらでも反転が要る、のどれかと、右送りなら実装のコードに書かれる `poly` と `init` の値（ビットを反転した値）を出す。`poly` については、ビットを反転した値の最下位ビットが 1 なら、定数だけでは通常表記か反転した値か決まらないことを添える。

### 共通

- 設定が不正なときは計算例と今の設定での補足を出さず、設定が不正であることを出す。
- サイドバーには今の設定（6 つのパラメータと入力）と、可視化のページへのリンクを置く。ステータスバーにはプリセット名（無ければ `custom`）を出す。
- URL のフラグメントは `#equivalence`。

## 14. 表引きのページ

多くのライブラリが使う、256 個の値の表（表 T）で 1 バイトずつ計算するやり方を、今の設定と入力（可視化のページと同じもの）で示す。1 ビットずつの計算（3 章）と同じ CRC になることと、表の各値が 1 ビットずつの計算の 8 クロック分であることを見せる。

- 向き: `refin` = `refout` = true なら右送り、それ以外は左送りの表を使う。左送りで `refin` が true なら入力の各バイトのビットの並びを反転してから使い、`refout` が true なら最後に結果を反転する、と添える。
- 表 T: 添え字 0〜255 の値を 16 × 16 の格子に並べる（行が上位 4 ビット、列が下位 4 ビット、値は `width` に見合う桁数の 16 進）。
  - 左送り: `T[i]` は、0 のレジスタ（3 章）に `i` の 8 ビットを最上位ビットから入れて 8 クロック回した値（`i(x)·x^width` を `g(x)` で割った余り）。
  - 右送り: `T[i]` は、0 のレジスタを右へシフトする実装で、`i` の 8 ビットを最下位ビットから入れて 8 クロック回した値（左送りの `T[i を 8 ビットで反転]` を `width` ビットで反転した値）。
- 表の値の作り方: 格子の値を選ぶと、その値を作る 8 クロックを 1 行ずつ（クロックの番号、入るビット、その後のレジスタの 2 進）並べる。最後の行が選んだ値になる。
- 1 バイトずつの計算: 更新の式と、入力の各バイトの行（バイト、前の `crc`、添え字（表の行と列に合わせて 16 進）、`T[添え字]`、後の `crc`）を並べ、最初に初期値、最後に出力の反転と `xorout` を施した結果を出す。
  - 更新の式は、左送りで `width` ≥ 8 なら `crc = ((crc << 8) & mask) ^ T[((crc >> (width − 8)) ^ byte) & 0xFF]`、`width` < 8 なら `crc = T[((crc << (8 − width)) ^ byte) & 0xFF]`、右送りなら `crc = (crc >> 8) ^ T[(crc ^ byte) & 0xFF]`。初期値は左送りなら `init`、右送りなら `init` を `width` ビットで反転した値。
  - 行を選ぶと、その行の添え字の値を格子で強調し、その値の作り方を出す。既定は最初の行。
  - 結果の下に、1 ビットずつ計算した CRC を並べ、一致することを示す。
- 入力が 8 ビットの倍数でないときは、1 バイトずつの計算を出さず、その理由を出す（表 T と作り方は出す）。
- 設定が不正なときは、設定が不正であることだけを出す。
- サイドバー・ステータスバーは置き換えのページ（13 章）と同じ。選んだ行や値は URL にも保存にも残さない。
- URL のフラグメントは `#table`。

## 15. 推定のページ

データとその CRC の組をいくつか入れると、それを満たすパラメータを探す。

- 組の入力: 行ごとにデータと CRC（16 進）を入れる。データの書き方はページで 1 つ選ぶ（`text` は UTF-8 のバイト列、`hex` は 16 進のバイト列）。行は足したり消したりでき、最初は 2 行。入れた組は URL にも保存にも残さない。
- `width`: 入力欄で決める。空なら、入れた CRC のうち一番長いものの桁数 × 4 とする。
- 探し方は 2 段で、「探す」を選ぶと両方を行い、結果を出す。
  1. カタログから: その `width` のプリセットのうち、全ての組でデータの CRC が入れた CRC と一致するもの。
  2. 総当たり: `width` が 16 以下のときだけ行う。`poly` は最下位ビットが 1 の全ての値、`refin`・`refout` は 4 通りを試す。
     - 長さの同じ組が 2 つ以上要る。長さの同じ組 a、b では `crc(a) ⊕ crc(b)` が `init` = `xorout` = 0 で計算した `crc(a ⊕ b)` に等しい（13 章の「初期値と最終 XOR の分」）ので、`init` と `xorout` によらず `poly` と `refin`・`refout` を絞れる。
     - 長さの違う組もあれば、`init` を全ての値で試して決め、`xorout` も決める。無ければ `init` と `xorout` は 1 つに決まらないので、`init` = 0 としたときの `xorout` を出し、決まらないことを添える。
     - 長さの同じ組が無ければ総当たりは行わず、その理由を出す。
  - 結果は候補ごとに 6 つのパラメータ（決まらない `init` はその旨）を出し、カタログにあればその正式名を添える。候補は最大 20 個まで出し、超えた数も示す。各候補に「可視化で開く」を置き、選ぶとその設定と最初の組のデータを入力にして可視化のページへ移る。
- サイドバーには、組の集め方の手がかり（長さの同じ組を 2 つ以上、長さの違う組も 1 つ以上入れると決まりやすい）を置く。ステータスバーには候補の数を出す。
- 入力に誤りがある行（16 進として読めない、CRC が `width` ビットに収まらない）は、その欄に誤りを出し、探さない。
- URL のフラグメントは `#estimate`。

## 18. 未規定

- 32 ビットを超える `width`（CRC-64 など）は扱わない。
- 携帯端末向けのレイアウト最適化は行わない（横幅 1024px 以上を想定）。
