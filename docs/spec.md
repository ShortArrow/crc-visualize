# CRC 可視化 SPA 仕様

LFSR（ハードウェア）の動きと、ビット単位 CRC 実装（ソフトウェア）の各行を、1 クロックずつ同期させて見せるブラウザアプリ。

## 1. CRC パラメータ（Rocksoft モデル）

| 名前 | 型 | 制約 |
|---|---|---|
| `width` | 整数 | 1〜32 |
| `poly` | 整数 | 0 < poly < 2^width（最上位の x^width 項は含めない） |
| `init` | 整数 | 0 ≤ init < 2^width |
| `refin` | 真偽 | 真なら入力の各バイトをビット反転してから投入する |
| `refout` | 真偽 | 真なら最終レジスタ値を `width` ビットで反転する |
| `xorout` | 整数 | 0 ≤ xorout < 2^width |

プリセットは reveng カタログの `check`（入力 `"123456789"` の CRC）を持ち、計算の正しさの基準にする。

- 教材用 `CRC-3/TUTORIAL`（width=3, poly=0x3, init=0, refin=false, refout=false, xorout=0, 入力ビット `10101`, CRC=`101`）
- CRC-3/GSM, CRC-4/G-704, CRC-5/USB, CRC-7/MMC, CRC-8/SMBUS, CRC-8/MAXIM-DOW, CRC-16/ARC, CRC-16/IBM-3740, CRC-16/XMODEM, CRC-16/KERMIT, CRC-32/ISO-HDLC, CRC-32/BZIP2

## 2. 入力

入力形式は次の 3 つから選ぶ。

| 形式 | 例 | ビット列への変換 |
|---|---|---|
| `bits` | `10101` | そのまま。長さは任意 |
| `hex` | `31 32 33` | 空白は無視。1 バイト = 8 ビット、MSB から |
| `text` | `123` | UTF-8 でバイト列にし、`hex` と同様に変換 |

- `refin` が真で、ビット長が 8 の倍数でない入力は不正とする。
- 入力ビット数の上限は 256。

## 3. ハードウェアモデル（直接型 LFSR）

レジスタは `r[width-1]`（MSB, 左端）から `r[0]`（右端）まで横に並び、1 クロックで左へシフトする。

1 クロックの更新規則は次のとおり。`b` は投入ビット。

```
fb      = r[width-1] XOR b
r'[0]   = fb AND poly[0]
r'[i]   = r[i-1] XOR (fb AND poly[i])   (1 ≤ i < width)
```

- XOR ゲートは `poly[i] = 1` の位置 `i` ごとに、`r[i]` の入口に 1 つ置く。`i = 0` のゲートは入力が `fb` だけなので、配線だけで表す。
- `b` と MSB の XOR ゲートはレジスタ左端の出口に置き、そこからフィードバック線が各ゲートへ伸びる。
- 初期値の 0 埋め（augmentation）は行わない。理由は [ADR-0001](adr/0001-direct-lfsr.md)。

## 4. ソフトウェア表示（擬似コード）

```c
crc = INIT;
for (bit b in input) {                 // refin: 各バイトを反転して MSB から
    fb  = ((crc >> (W-1)) & 1) ^ b;
    crc = (crc << 1) & MASK;
    if (fb == 1) {
        crc ^= POLY;
    }
}
if (REFOUT) crc = reflect(crc, W);
crc ^= XOROUT;
```

現在のステップに対応する行をハイライトする。`fb == 0` のステップでは `if` の本体を飛ばしたことが分かる表示にする。

## 5. ステップ列（状態遷移）

計算は純粋関数 `trace(params, inputBits)` が `Step[]` として返し、描画はステップを読むだけにする。各ステップはその時点のレジスタ値を持つ。

| 種類 | Given | Then |
|---|---|---|
| `init` | 計算開始 | `reg = init` |
| `reflectIn` | `refin` 真でバイトの先頭 | 次の 8 ビットが反転した順に並び替わる。`reg` は不変 |
| `feedback` | 投入ビット `b` | `fb = msb XOR b` が決まる。`reg` は不変 |
| `shift` | `feedback` の直後 | `reg = (reg << 1) & MASK` |
| `xor` | `shift` の直後で `fb = 1` | `reg ^= poly`。`fb = 0` ならこのステップは置かず、`shift` で終わる |
| `reflectOut` | 全ビット投入後、`refout` 真 | `reg = reflect(reg, width)` |
| `xorOut` | `reflectOut` の後（無ければ全投入後） | `reg ^= xorout` |
| `done` | 最終 | `reg` が CRC。入力の後ろに CRC を連結して表示する |

`reflectOut` は `refout` 偽のとき、`xorOut` は `xorout = 0` のときに省く。

## 6. 再生

- 操作: 再生 / 一時停止、1 ステップ進む / 戻る、先頭 / 末尾へ移動、シークバー、速度倍率（0.25〜8）、ループ再生の切り替え。
- ループ再生: 有効なら、再生中に `done` を表示し終えたら先頭に戻って再生を続ける。無効なら `done` で停止する。速度設定と同様、CRC 設定を変えても保持する。
- 速度ランプ: 自動モードでは、`fb = 0` と `fb = 1` のクロックをそれぞれ 1 回以上見せ終わるまで低速（1 ステップ 900 ms）で再生し、その後のクロックは高速（120 ms）にする。片方の値しか出ない入力でも、低速は最初の 6 クロックまでとする。`init`・`reflectOut`・`xorOut`・`done` は常に低速。一定モードでは全ステップ 600 ms。どちらのモードでも時間は速度倍率で割る。
- 設定や入力を変えたら、ステップ列を作り直して先頭に戻り、停止する。
- 設定が不正な場合は、項目ごとのエラーを表示し、描画は直前の有効な状態を残さず空にする。

## 7. 画面

ダークモード（エディタ風）の 1 画面構成とする。

1. 設定パネル: プリセット選択、各パラメータ、入力形式と入力値。
2. 上段: LFSR 図。入力ストリーム（投入済みは暗く、次のビットは強調）、レジスタ箱、XOR ゲート、フィードバック線。`fb = 1` の間はフィードバック線と XOR ゲートを赤く光らせ、`fb = 0` の間は灰色の点線にする。XOR ゲートは計算に使われるステップ（入力ゲートは `feedback`、タップのゲートは `xor`）でだけ点灯させ、横にその計算式（例: `0⊕1=1`）を出す。

色は 1 色に 1 つの意味だけを持たせる。

| 色 | 意味 |
|---|---|
| 赤 | `fb = 1` の経路（フィードバック線、XOR で値が変わる箱） |
| 黄 | 今計算しているもの（点灯中のゲート、MSB、次の入力ビット） |
| 灰 | 使われていないもの |
| 緑 | 完了した CRC |

図には凡例として、⊕ の意味と色の意味を添える。
3. 下段: 擬似コード（現在行をハイライト）と、レジスタ値の 2 進 / 16 進表示。
4. 再生コントロール。

`done` ではレジスタを緑に光らせ、「入力 + CRC」のビット列を表示する。

## 8. 未規定

- 32 ビットを超える `width`（CRC-64 など）は扱わない。
- 携帯端末向けのレイアウト最適化は行わない（横幅 1024px 以上を想定）。
