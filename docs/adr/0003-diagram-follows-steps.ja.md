# ADR-0003: LFSR 図の XOR はステップの分け方に合わせ、箱の真下で箱自身とフィードバックを合流させる

- 状態: 採用
- 日付: 2026-10-11

## 文脈

ハードウェアの LFSR は 1 クロックで `r'[i] = r[i-1] XOR (feedback AND poly[i])` を計算する。教科書の図では、XOR ゲートを `r[i-1]` と `r[i]` の間に置き、`r[i-1]` の出力とフィードバックを合流させて `r[i]` に入れる。

一方この可視化は、擬似コードの行と同期させるため、1 クロックを `shift`（`crc = (crc << 1) & mask`）と `xor`（`crc ^= poly`）の 2 ステップに分けている。

ゲートを箱の間（横一列、のちに箱の間の下に Y 字）に置いたところ、次の食い違いが出た。

- `xor` のステップでは既にシフトが済んでおり、`r[i-1]` には別の値が入っている。それでも図は「`r[i-1]` とフィードバックの XOR を `r[i]` に入れる」ように見える。
- `shift` のステップで、タップの位置の値がゲートの下をくぐって移る不自然な動きになる。

## 決定

LFSR 図はステップの分け方に合わせる。

- 箱はすべて横線でつなぎ、`shift` では全ての値が真横に滑る。
- XOR ゲートは `poly[i] = 1` の各 `r[i]`（`i = 0` を含む）の真下に置く。`xor` では `r[i]` の値が左の脚を下り、下から来るフィードバックとゲートで合流し、結果が右の脚を上がって `r[i]` に戻る。

## 理由

- 図の各ステップが、同時にハイライトされる擬似コードの 1 行（`<<` と `^=`）と同じことをしている。
- `xor` の入力が「その箱の今の値」と「フィードバック」で、画面に見えている値そのものになる。
- `r[0]` も「シフトで 0 が入り、`xor` で下から XOR される」の 2 段で、他のタップと同じ形になる。

## 採らなかった案

- ゲートを `r[i-1]` と `r[i]` の間に置く（ハードウェアの 1 クロックそのまま）: 上記の食い違いが残る。
- Y 字は残し、`shift` だけ横に滑らせる: 箱の間に横線と Y 字の 2 経路が並び、値がどちらを通るのか曖昧になる。
